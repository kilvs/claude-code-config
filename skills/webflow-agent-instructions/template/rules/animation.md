# Animation

- Motion is **Webflow's native Interactions with GSAP (IX3)**, and only that. Never Classic Interactions (IX2). Never a custom-code GSAP script for tweens; JavaScript may hold state (the state helper for nav dropdowns) and fire IX3 custom events, nothing more.
- Elements opt into motion with the site presets: `data-animate="fade-up"` and the other values in the `interactions` skill. Never author a one-off tween for something a preset already does. Different timing means a page- or component-scoped copy of the preset, logged; there is no per-element delay or duration attribute.
- The nav is the one behaviour, built from divs, links and real `button`s, **never the native Webflow Navbar element** (1 Oct 2026). The state helper holds open/closed state, ARIA and the panels' `is-open` classes; IX3 custom-event interactions (`nav-open`, `nav-menu-open`) do the motion. Accordions and tabs are not presets; build them per site in the Designer when a site needs them.
- Every interaction carries playback rules: reveals `skip-to-end` under reduced motion, loops and parallax `dont-animate`, parallax off on 767 and 479.
- Fail visible: the from-state lives in the interaction, never in a class at `opacity: 0`. Animate transforms and opacity only, never layout properties.
- **Never animate the LCP element** (usually the hero image). IX3 keeps every interaction target at `visibility: hidden` until its runtime loads in the footer, which pushed a mobile LCP to 5.7s. Animate the hero copy if the design wants motion; the hero image paints on load.
- **Assess every SVG before it enters Webflow** (including SVGs ported from a Vercel preview): read the source's CSS, keyframes, transitions, hover states and scripts for anything that targets the SVG or its children. Anything moves or changes inside it → **Custom Element** (inline SVG as `svg > g > path` elements, one group per moving part). Nothing moves inside it → **uploaded SVG image**. The whole SVG fading up or parallaxing as one does not count as animated.
- **Animated graphics are never images.** If any part of a graphic moves on its own (a loop, a draw-in, a per-part reveal or parallax), build it as divs (or Custom Elements where an SVG shape itself must move), one element per moving part, so IX3 or the section's CSS can drive it. Only a graphic that is static inside may be an uploaded SVG image; the whole graphic moving as one (fade-up, parallax on its wrapper) does not make it animated.
- Motion from Figma, Relume, GitHub or IX2 is mapped to a preset first; unmapped motion is flagged, never approximated silently.
