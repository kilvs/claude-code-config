# Platform notes (Webflow / WordPress / Shopify)

The audit criteria are the same everywhere; *how you apply a fix* depends on the platform. Identify the platform first, then give fixes in the form that platform actually accepts. Giving someone a raw server-config fix for a hosted no-code platform wastes their time.

## How to identify the platform
- **Webflow:** `Generated by Webflow` HTML comment, `wf-` classes, `webflow.js`, assets on `assets.website-files.com` / `cdn.prod.website-files.com`.
- **WordPress:** `/wp-content/`, `/wp-includes/`, `wp-json`, generator meta `WordPress`, common theme/plugin paths.
- **Shopify:** `cdn.shopify.com`, `Shopify.theme`, `/cdn/shop/`, `.myshopify.com`, `window.Shopify`.
- **Custom/unknown:** treat generically; give standard HTML/CSS/JS/server fixes.

## Webflow
- **Strengths:** HTTPS automatic; clean semantic output possible; per-page SEO fields built in.
- **Where fixes go:**
  - SEO title/description/OG → Page Settings (per page); sitemap/robots → Site Settings → SEO.
  - Canonical, JSON-LD, custom `<head>` → Page Settings → Custom Code (head) or Site-wide Custom Code.
  - Semantic tags → element Tag setting (set `H1`, `nav`, `main`, etc.); alt text → asset/element settings.
  - Focus states → the element's **Focused** state in the Designer.
  - Performance: Webflow minifies on publish; image optimization via the asset settings / responsive images; lazy-load toggle per image. Heavy interactions/3rd-party embeds are the usual CWV cost.
- **Constraints to flag:** limited control over response/security headers on standard hosting; some Best-Practices header fixes simply aren't available — say so rather than prescribing them.

## WordPress
- **Strengths:** highly fixable; plugins/themes for almost everything.
- **Where fixes go:**
  - SEO (titles, meta, canonical, OG, sitemap, schema) → an SEO plugin (Yoast / Rank Math). Recommend configuring there over hand-editing the theme.
  - Performance → caching plugin, image optimization plugin, CDN; defer/async via plugin or theme; reduce plugin bloat (often the root cause).
  - Headers / HTTPS → host config or a security plugin; force-HTTPS setting.
  - Accessibility/markup → theme template + CSS edits; choose an a11y-ready theme.
- **Constraints to flag:** plugins are frequently the *source* of perf/console/a11y problems — isolate the offending plugin. **Accessibility "overlay" plugins do not create conformance and can make things worse — advise against them.**

## Shopify
- **Strengths:** HTTPS automatic; fast CDN; many themes emit `Product` schema already.
- **Where fixes go:**
  - SEO title/description per product/collection/page → admin; theme-level OG/schema → `theme.liquid` / section `.liquid`. Check existing schema before adding (avoid duplicates).
  - Performance → image sizing via Liquid `image_url` filters + `srcset`; defer non-critical JS in theme; minimize apps (each app injects scripts → INP/LCP cost). Audit installed apps.
  - Accessibility/markup → theme `.liquid` + CSS; alt text per image in admin.
- **Constraints to flag:** response/security headers are largely managed by Shopify with limited merchant control — note this; most actionable fixes are in theme code and app reduction.

## General fix-form rule
When you have the user's **files**, edit them directly. When you only have a **URL** on a hosted platform, give the exact paste-ready snippet **and** name where it goes in that platform's UI (e.g. "paste into Webflow → Page Settings → Custom Code → Head"). Never hand a fix the platform can't accept.
